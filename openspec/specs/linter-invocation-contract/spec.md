# linter-invocation-contract Specification

## Purpose
Единый контракт вызова линтера, пригодный для слабейшей модели: набор CLI-команд, формат JSON
вывода и коды возврата, по которым вызывающая сторона однозначно отличает успех, нарушение и
ошибку вызова.

## Requirements

### Requirement: Команда валидации структуры

Система SHALL предоставлять команду валидации, принимающую идентификатор эталона и путь к проекту,
и выводящую вердикт. Формат вывода MUST переключаться между машиночитаемым (JSON) и человекочитаемым.

#### Scenario: Валидация проекта по эталону

- **WHEN** вызвана команда валидации с идентификатором эталона и путём к проекту в формате JSON
- **THEN** в стандартный вывод печатается вердикт по схеме вердикта

### Requirement: Однозначные коды возврата

Система SHALL возвращать код `0` при статусе `ok`, код `1` при найденных нарушениях и код `2` при
ошибке вызова или окружения (шаблон не найден, путь недоступен, шаблон не проходит схему). Поле
`status` вердикта MUST дублировать смысл кода возврата.

#### Scenario: Структура соответствует эталону

- **WHEN** валидация не нашла нарушений
- **THEN** код возврата `0`, а `status` равен `ok`

#### Scenario: Найдены нарушения

- **WHEN** валидация нашла хотя бы одно нарушение
- **THEN** код возврата `1`, а `status` равен `violations`

#### Scenario: Ошибка вызова

- **WHEN** указанный эталон не найден или путь к проекту недоступен
- **THEN** код возврата `2`, а `status` равен `error` с кодом и сообщением ошибки

### Requirement: Обнаружимость эталонов

Система SHALL предоставлять команду перечисления доступных эталонов с их идентификатором, версией и
языком, чтобы вызывающая сторона выбирала эталон из известного множества, а не угадывала его.

#### Scenario: Перечень эталонов

- **WHEN** вызвана команда перечисления эталонов в формате JSON
- **THEN** выводится список доступных эталонов с идентификатором, версией и языком

#### Scenario: Авто-подбор эталона по маркерам

- **WHEN** валидация вызвана с указанием авто-подбора эталона
- **THEN** система выбирает эталон по маркерам обнаружения либо возвращает ошибку вызова, если
  подходящий эталон не найден

### Requirement: Выдача схем контракта

Система SHALL выдавать замкнутые схемы контракта (вход, эталон, вердикт) по запросу, чтобы
вызывающая сторона могла проверить свои данные по той же схеме, что и линтер.

#### Scenario: Запрос схемы вердикта

- **WHEN** запрошена схема вердикта
- **THEN** выводится действующая JSON Schema вердикта

### Requirement: Самодостаточная поставка образом

Система SHALL поставляться исполнимым образом, содержащим встроенные эталоны и схемы, и запускаться
без хостовых зависимостей, кроме среды контейнеров. Код возврата контейнера MUST совпадать с кодом
возврата линтера.

#### Scenario: Запуск в контейнере пробрасывает код возврата

- **WHEN** линтер запущен в контейнере на смонтированном проекте и нашёл нарушения
- **THEN** контейнер завершается с кодом `1`, доступным вызывающей стороне
