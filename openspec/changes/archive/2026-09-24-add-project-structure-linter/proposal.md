## Why

Genesis (харнесс развёртывания окружений) по принципу «одна система — одно дело» выносит валидацию
структуры проекта в отдельную Harness-систему, а сейчас такой системы нет. Нужен детерминированный
инструмент, который проверяет структуру проекта по курируемому эталону и возвращает машиночитаемый
вердикт по единому контракту — так, чтобы его надёжно вызвала даже слабейшая модель, а не только
сильная облачная.

## What Changes

- Вводится CLI-линтер структуры проекта, поставляемый как Docker-образ (запуск в любом окружении
  без хостовых зависимостей).
- Вводится модель данных эталона (шаблона) структуры: версионированные данные (`templates/<id>/<version>/template.yaml`),
  а не md-документы и не логика, зашитая в код.
- Вводится замкнутый контракт вход/выход (JSON Schema для входа, шаблона и вердикта) — Standard 22.
- Вводится классификация нарушений: отсутствует обязательный путь, присутствует запрещённый,
  нарушено имя, нарушена разметка слоя.
- Вводятся коды возврата `0`/`1`/`2` (ok / нарушения / ошибка вызова) для однозначного различения
  исходов вызывающей стороной.
- Вводится discoverability шаблонов (`list-templates`) и авто-подбор (`--template auto`), чтобы
  слабой модели не приходилось угадывать шаблон.
- В скоуп v1 входит **только** валидация структуры (пути/файлы/имена + разметка слоёв путями).
  Анализ графа импортов, стилевой линт, версии и генерация скелета — вне скоупа.

## Capabilities

### New Capabilities
- `structure-validation`: приём структуры проекта и эталона по замкнутой схеме, детерминированная
  проверка по правилам (обязательные/запрещённые пути, имена, разметка слоёв), возврат вердикта с
  классифицированными нарушениями (путь + причина) и однозначным кодом статуса.
- `structure-template-model`: модель данных курируемого эталона структуры — версионированные
  данные и их замкнутая схема, отдельная от логики проверки.
- `linter-invocation-contract`: единый контракт вызова для слабой модели — CLI-команды
  (`validate`, `list-templates`, `schema`, `version`), формат JSON вывода и коды возврата.

## Impact

- Новый код: `cmd/struct-linter`, `internal/structlint/{domain,application,infrastructure}`.
- Новые данные: `templates/**`, `schemas/{input,template,verdict}.schema.json`, `testdata/**`.
- Поставка: `docker/struct-linter/Dockerfile`, обёртка `tools/struct-linter/lint.sh`, цели `Makefile`,
  сервис в `docker-compose.yml`.
- Зависимости: заводится `go.mod` (проект ранее без Go-кода).
- Потребители: Genesis-оркестратор и любой агент/проект, вызывающий линтер по контракту.
