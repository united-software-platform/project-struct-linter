## Purpose

Модель данных курируемого эталона структуры: версионированные данные и их замкнутая схема, отдельные
от логики проверки, — чтобы правила менялись контролируемо, а не зашивались в код или md-документы.

## ADDED Requirements

### Requirement: Эталон задаётся данными, а не кодом

Система SHALL считывать эталон структуры из данных (файл шаблона), а не из логики проверки. Правила
(обязательные, запрещённые пути, именование, разметка слоёв) MUST быть выражены полями данных.

#### Scenario: Смена правил без правки кода проверки

- **WHEN** сопровождающий меняет правило в файле шаблона
- **THEN** поведение валидации меняется соответственно без изменения кода движка проверки

### Requirement: Замкнутая схема эталона

Система SHALL проверять файл шаблона по замкнутой схеме перед использованием. Поле или значение вне
схемы MUST приводить к отказу загрузки шаблона, а не к его молчаливому игнорированию.

#### Scenario: Неизвестное поле в шаблоне

- **WHEN** файл шаблона содержит поле, не описанное схемой
- **THEN** загрузка шаблона завершается ошибкой с указанием поля и причины

#### Scenario: Недопустимое значение перечисления

- **WHEN** поле шаблона (`kind`, `match`) содержит значение вне допустимого множества
- **THEN** загрузка шаблона завершается ошибкой с указанием поля и допустимых значений

### Requirement: Версионирование эталонов

Система SHALL адресовать эталон парой «идентификатор + версия» и хранить версии раздельно, чтобы
один идентификатор мог иметь несколько версий. Каждый шаблон MUST содержать `schema_version`,
`id`, `version` и `language`.

#### Scenario: Выбор конкретной версии эталона

- **WHEN** вызов указывает идентификатор и версию эталона
- **THEN** применяется именно эта версия шаблона

#### Scenario: Версия не указана

- **WHEN** вызов указывает только идентификатор эталона без версии
- **THEN** применяется последняя доступная версия этого идентификатора
