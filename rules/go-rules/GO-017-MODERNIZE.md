# Go: Модернизация кода
Перевод кода на актуальные возможности языка и stdlib: замена deprecated API, современные builtins, пакеты `slices`/`maps`, `sync.OnceValue`, итераторы и обновлённые тест/бенч-паттерны.

## Таблица правил
| ID | Правило |
|----|---------|
| MOD-001 | Заменять `interface{}` на `any` для type parameters и пустого интерфейса. |
| MOD-002 | Использовать builtins `min`/`max` вместо ручных реализаций (Go 1.21+). |
| MOD-003 | Использовать `range n` вместо `for i := 0; i < n; i++` (Go 1.22+). |
| MOD-004 | Использовать пакеты `slices`/`maps` (`slices.Sort`, `slices.Contains`, `maps.Clone`). |
| MOD-005 | Использовать `sync.OnceValue`/`sync.OnceFunc` вместо ручного кэша на `sync.Once` (Go 1.21+). |
| MOD-006 | Обрабатывать большие данные через итераторы `iter.Seq` (Go 1.23+). |
| MOD-007 | В бенчмарках использовать `b.Loop()` вместо `for range b.N` (Go 1.24+). |
| MOD-008 | В тестах использовать `t.Context()` вместо `context.Background()` (Go 1.24+). |
| MOD-009 | Использовать `//go:embed` для статических ассетов вместо чтения по путям. |
| MOD-010 | Заменять устаревший `math/rand` на `math/rand/v2` для не-криптографической случайности. |
| MOD-011 | Для структурированного логирования использовать `log/slog` (или проектный логгер). |
| MOD-012 | Запускать `golangci-lint` с modernize-линтером для автоматической проверки. |

## Принцип
Код стоит непрерывно приводить к актуальным идиомам: новые builtins и пакеты stdlib короче, безопаснее по типам и лучше оптимизируются компилятором. Модернизацию применяют инкрементально — маленькими безопасными шагами при обычных правках, а не большим рефакторингом. Автоматический modernize-линтер находит устаревшие паттерны, а `.modernize` помнит осознанно отклонённые предложения.

| Понятие | Описание |
|---------|----------|
| `Deprecated API` | Устаревший пакет/функция с современной заменой (`math/rand` → `math/rand/v2`). |
| `Builtin` | Встроенная функция языка (`min`, `max`), не требующая реализации. |
| `Iterator` | `iter.Seq`/`iter.Seq2` для ленивого перебора без загрузки данных в память. |

## Подробное описание

**[MOD-001]** Используйте `any` вместо `interface{}` — это тот же тип, но идиоматичнее и читаемее, особенно в generic-ограничениях (`[T any]`).

**[MOD-002]** Встроенные `min`/`max` (Go 1.21+) заменяют ручные хелперы — меньше кода и багов.

**[MOD-003]** `for i := range n` (Go 1.22+) заменяет классический счётный цикл, когда индекс идёт от 0 до n.

**[MOD-004]** Операции над срезами и картами делайте через `slices`/`maps`: `slices.Sort`, `slices.SortFunc`, `slices.Contains`, `maps.Clone`, `maps.Clear` — вместо ручных циклов.

**[MOD-005]** Для ленивой инициализации/кэша используйте `sync.OnceValue`/`sync.OnceFunc` (Go 1.21+) вместо ручной пары `value + sync.Once` — атомарнее и без гонок.

**[MOD-006]** Большие данные перебирайте итераторами `iter.Seq` (Go 1.23+) — константная память вместо загрузки всего набора.

**[MOD-007]** В бенчмарках используйте `for b.Loop()` (Go 1.24+) вместо `for range b.N` — корректнее по семантике и оптимизации.

**[MOD-008]** В тестах берите `ctx := t.Context()` (Go 1.24+) — он наследует таймаут/отмену теста, в отличие от `context.Background()`.

**[MOD-009]** Статические ассеты встраивайте через `//go:embed`, а не читайте по относительным путям в рантайме — надёжнее при деплое.

**[MOD-010]** Устаревший `math/rand` заменяйте на `math/rand/v2` для не-криптографической случайности. Для секретов и токенов используйте `crypto/rand` (см. [[GO-015-SECURITY]]).

**[MOD-011]** Логируйте структурированно через `log/slog` или принятый в проекте логгер — вместо разрозненных сторонних логгеров.

**[MOD-012]** Прогоняйте `golangci-lint` с modernize-линтером (актуальная версия) — он автоматически находит устаревшие паттерны; ранее отклонённые предложения фиксируйте в `.modernize`, чтобы не предлагать повторно.

> **Важно:** модернизацию применяйте инкрементально. Крупный рефакторинг «заодно» с другой задачей смешивает изменения и усложняет ревью.

## Пример

```go
// [MOD-002][MOD-003] builtins и range n
for i := range 10 {
    _ = i
}
result := max(a, b)
smallest := min(x, y, z)

// [MOD-004] slices/maps
slices.SortFunc(users, func(a, b User) int { return a.ID - b.ID })
found := slices.ContainsFunc(users, func(u User) bool { return u.ID == id })
```

```go
// ❌ Нарушение [MOD-001][MOD-005]
func Process[T interface{}](data T) {}

var (
    value string
    once  sync.Once
)
func getConfig() string {
    once.Do(func() { value = loadConfig() })
    return value
}

// ✅ Правильно
func Process[T any](data T) {}

var getConfig = sync.OnceValue(loadConfig)
```

```go
// [MOD-007][MOD-008] современные тест/бенч-паттерны
func BenchmarkProcess(b *testing.B) {
    for b.Loop() {
        process()
    }
}

func TestGetUser(t *testing.T) {
    ctx := t.Context()
    _ = ctx
}
```

## Исключения и граничные случаи
| Ситуация | Как поступить |
|----------|---------------|
| Модуль на старой версии Go | Применять только фичи, доступные в `go.mod`-версии; обновлять инкрементально (MOD-003/005/007). |
| Секреты и токены | Использовать `crypto/rand`, а не `math/rand/v2` (MOD-010, [[GO-015-SECURITY]]). |
| Осознанно отклонённое предложение линтера | Зафиксировать в `.modernize`, чтобы не всплывало повторно (MOD-012). |
