## Таблица правил
| ID | Правило |
|----|---------|
| PAT-001 | Публичные конструкторы делать через functional options (`opts ...Option`). |
| PAT-002 | Не использовать `init()` для настройки сервисов — только явные конструкторы, возвращающие `error`. |
| PAT-003 | Не использовать mutable globals — передавать зависимости явно. |
| PAT-004 | Размещать sentinel `Unknown` в `iota 0` у enum. |
| PAT-005 | Компилировать regexp один раз на уровне пакета, а не в каждом вызове. |
| PAT-006 | Ставить `defer Close()` сразу после `Open()`. |
| PAT-007 | В retry-логике проверять `ctx.Err()` на каждой итерации. |
| PAT-008 | Ограничивать ресурсы: размер пула, глубину очереди, буфер. |
| PAT-009 | Собирать строки в циклах через `strings.Builder`. |
| PAT-010 | Обрабатывать большие данные потоково/итераторами (Go 1.23+), не загружая всё в память. |
| PAT-011 | Для ключей/токенов использовать `crypto/rand`, для прочего — `math/rand/v2`. |

## Принцип
Идиоматичный Go-код делает зависимости и жизненный цикл явными. Functional options позволяют API расти без слома сигнатур, явные конструкторы вместо `init()` дают тестируемость и обработку ошибок, а `defer Close()` рядом с `Open()` исключает утечки ресурсов на error-путях. Ограниченные пулы защищают от OOM под нагрузкой, а `crypto/rand` — от предсказуемых токенов. Общая нить: никакого скрытого глобального состояния и никаких неограниченных ресурсов.

| Понятие | Описание |
|---------|----------|
| `Functional option` | Функция `func(*T)`, настраивающая объект; передаётся вариативно в конструктор. |
| `Sentinel iota 0` | Нулевое значение enum, означающее «неизвестно/невалидно». |
| `Bounded resource` | Ресурс с жёстким верхним пределом (пул, очередь, буфер). |

## Подробное описание

**[PAT-001]** Публичные конструкторы принимают вариативные опции: `NewServer(addr, opts ...Option)`. Это позволяет добавлять параметры без изменения сигнатуры и ломки вызовов.

**[PAT-002]** `init()` для настройки сервисов создаёт скрытые зависимости, не возвращает ошибку и мешает тестам. Используйте явный `NewService() (*Service, error)`.

**[PAT-003]** Изменяемые глобальные переменные — скрытая связь и головная боль для тестов. Передавайте зависимости через конструктор/параметры.

**[PAT-004]** Размещайте `Unknown` в `iota 0`: тогда неинициализированная переменная enum имеет безопасное значение «неизвестно», а не молчаливо валидное первое состояние.

**[PAT-005]** `regexp.MustCompile` в теле функции компилирует шаблон на каждый вызов. Компилируйте один раз на уровне пакета (`var re = regexp.MustCompile(...)`) или лениво через `sync.Once`.

**[PAT-006]** `defer Close()` ставьте сразу после успешного `Open()`. Иначе на любом error-пути ниже ресурс утечёт.

**[PAT-007]** В retry с backoff проверяйте `ctx.Err()` на каждой итерации (через `select { case <-ctx.Done(): ... }`), иначе цикл продолжится после отмены.

**[PAT-008]** Любой растущий ресурс (пул соединений, очередь, буфер) должен иметь предел. Неограниченный рост под нагрузкой ведёт к OOM.

**[PAT-009]** Конкатенация `+` в цикле аллоцирует новую строку на каждом шаге. Используйте `strings.Builder` — одна аллокация на `String()`.

**[PAT-010]** Большие данные обрабатывайте потоково (`bufio.Scanner`) или итераторами `iter.Seq` (Go 1.23+) — константная память вместо загрузки всего в heap.

**[PAT-011]** Для секретов (ключи, токены, session ID) используйте `crypto/rand`. `math/rand` предсказуем и создаёт уязвимость; для не-крипто нужд подойдёт `math/rand/v2`.

> **Важно:** enum без `Unknown` в нуле (нарушение PAT-004) даёт молчаливые баги: `var s Status` равно первому объявленному состоянию, которое выглядит валидным.

## Пример

```go
// [PAT-001] functional options
type Option func(*Server)

func WithMaxConns(n int) Option { return func(s *Server) { s.maxConns = n } }

func NewServer(addr string, opts ...Option) *Server {
    s := &Server{addr: addr, maxConns: 100}
    for _, opt := range opts {
        opt(s)
    }
    return s
}
// Использование: NewServer(":8080", WithMaxConns(500))
```

```go
// ❌ Нарушение [PAT-002] — init() скрывает зависимость и не вернёт ошибку
var db *sql.DB
func init() {
    var err error
    db, err = sql.Open("postgres", os.Getenv("DATABASE_URL"))
    if err != nil {
        log.Fatal(err)
    }
}

// ✅ Правильно — явный конструктор с ошибкой
func NewDatabase(cfg Config) (*Database, error) {
    db, err := sql.Open("postgres", cfg.URL)
    if err != nil {
        return nil, err
    }
    return &Database{db: db, pool: NewConnectionPool(cfg.MaxConns)}, nil
}
```

```go
// [PAT-005] regexp компилируется один раз на уровне пакета
var emailRegex = regexp.MustCompile(`[a-z0-9._%+-]+@[a-z0-9.-]+\.[a-z]{2,}`)

func FindEmails(text string) []string {
    return emailRegex.FindAllString(text, -1)
}
```

## Исключения и граничные случаи
| Ситуация | Как поступить |
|----------|---------------|
| `init()` для регистрации driver/кодека | Допустим для package-level регистрации, но не для setup сервисов (PAT-002). |
| Небольшая фиксированная строка | `+` допустим вне цикла; `Builder` нужен именно в циклах (PAT-009). |
| Валидация опций | Functional options не валидируют между собой — проверяйте в конструкторе после применения (PAT-001). |
