## Таблица правил
| ID | Правило |
|----|---------|
| NAME-001 | Все идентификаторы записывать в MixedCaps/mixedCaps, без подчёркиваний. |
| NAME-002 | Имена пакетов — lowercase, одно слово; суффикс `_test` допустим. |
| NAME-003 | Экспортируемые имена — UpperCamelCase, неэкспортируемые — lowerCamelCase. |
| NAME-004 | Константы именовать в MixedCaps, а не в `ALL_CAPS`. |
| NAME-005 | Receiver именовать аббревиатурой из 1–2 букв, единообразно во всех методах типа. |
| NAME-006 | Sentinel-ошибки именовать с префиксом `Err`, типы ошибок — с суффиксом `Error`. |
| NAME-007 | Булевы поля и функции именовать с префиксом `is`/`has`/`can`. |
| NAME-008 | Акронимы писать целиком заглавными или целиком строчными (`URL`, `json`), не `Url`/`Json`. |
| NAME-009 | Избегать «заикания» (stuttering): `http.Client`, а не `http.HTTPClient`. |
| NAME-010 | Геттеры именовать без `Get`: `user.Name()`, а не `user.GetName()`. |
| NAME-011 | Конструкторы именовать `New` или `NewTypeName` для одного primary type. |
| NAME-012 | Интерфейсы одного метода именовать по методу с суффиксом `-er` (`Reader`, `Writer`). |
| NAME-013 | Именовать по роли, а не по значению; длина имени пропорциональна области видимости. |
| NAME-014 | Строки ошибок писать со строчной буквы и без завершающей пунктуации. |
| NAME-015 | Использовать вариативные суффиксы/префиксы: `WithContext`, `In`, `Must`, `With<Field>`. |

## Принцип
Именование в Go тесно связано с механизмом видимости: экспорт определяется регистром первой буквы. Инструменты (`gofmt`, `revive`, `godoc`) предполагают MixedCaps повсюду, поэтому отклонения ломают tooling и читаемость. Хорошее имя описывает роль сущности, а не её текущее значение, и по длине соответствует области видимости: короткое в узком scope, развёрнутое в широком.

| Понятие | Описание |
|---------|----------|
| `MixedCaps` | Слова склеиваются с заглавной каждого слова, без подчёркиваний. |
| `Stuttering` | Дублирование имени пакета в имени типа (`http.HTTPClient`). |
| `Sentinel error` | Заранее объявленная переменная-ошибка для сравнения (`ErrNotFound`). |

## Подробное описание

**[NAME-001]** Используйте MixedCaps (экспортируемые) или mixedCaps (внутренние). Подчёркивания конфликтуют с конвенцией и флагаются линтерами. Исключение — имена в тестах допускают `_test`.

**[NAME-002]** Имя пакета — короткое существительное в нижнем регистре, одно слово: `json`, `http`, `user`. Избегайте пакетов `util`/`helper` — они не несут информации о содержимом.

**[NAME-003]** Экспорт управляется регистром: `UpperCamelCase` — публичное API, `lowerCamelCase` — внутреннее. Экспортируйте только то, что действительно нужно потребителю.

**[NAME-004]** Константы — это MixedCaps (`MaxRetries`, `defaultTimeout`). `ALL_CAPS` в Go зарезервировано не под «важность», а вовсе не используется — это стиль C.

**[NAME-005]** Receiver именуйте 1–2 буквами (`s *Server`, `b *Buffer`), одинаково во всех методах типа. `this`/`self` не используются.

**[NAME-006]** Sentinel-ошибки — переменные с префиксом `Err` (`ErrNotFound`). Типы ошибок — с суффиксом `Error` (`ValidationError`).

**[NAME-007]** Булевы поля/функции начинайте с `is`/`has`/`can` (`isConnected`, `hasPermission`). Голое прилагательное (`connected`) неоднозначно.

**[NAME-008]** Акронимы пишите единым регистром: `URL`, `HTTP`, `ID` или `json`. Смешанный `Url`, `Json` создаёт неоднозначность.

**[NAME-009]** Имя пакета всегда присутствует в квалифицированном имени, поэтому не повторяйте его в типе: `http.Client`, а не `http.HTTPClient`; `NewUser()`, а не `NewUserUser()`.

**[NAME-010]** Опускайте `Get` в геттерах: `user.Name()` звучит естественно. `Set`, наоборот, оставляют.

**[NAME-011]** Для типа-«главного» в пакете конструктор — `New()`; при нескольких типах — `NewTypeName()`.

**[NAME-012]** Интерфейс с одним методом называйте по методу с суффиксом `-er`: `Reader`, `Writer`, `Scanner`. Не добавляйте суффикс `Interface`.

**[NAME-013]** Именуйте по роли: значения меняются, роль — нет. Enum начинайте с имени типа, а zero value делайте «unknown»/невалидным, чтобы ловить неинициализированные значения.

**[NAME-014]** Строки ошибок — со строчной буквы, без точки в конце: `errors.New("invalid message id")`. Они часто оборачиваются и конкатенируются.

**[NAME-015]** Для вариантов функций применяйте устоявшиеся аффиксы: `WithContext` (контекст), `In` (in-place), `Must` (паника вместо ошибки), `With<Field>` (функциональные опции).

> **Важно:** Enum на `iota` без sentinel-значения делает валидное состояние равным zero value — неинициализированная переменная будет выглядеть корректной. Резервируйте 0 под `Unknown`.

## Пример

```go
// [NAME-002] пакет — lowercase, одно слово
package json

// [NAME-003] экспорт — UpperCamelCase; внутреннее — lowerCamelCase
type Request struct{}
var maxPacketSize int

// [NAME-004] константы — MixedCaps
const MaxRetries = 3
const defaultTimeout = 5 * time.Second

// [NAME-005] receiver — 1–2 буквы
func (s *Server) Start() error { return nil }

// [NAME-006] sentinel-ошибка и тип ошибки
var ErrNotFound = errors.New("not found")
type ValidationError struct{}

// [NAME-007] булевы поля с префиксом
type User struct {
    isConnected   bool
    hasPermission bool
}

// [NAME-012] интерфейс с суффиксом -er
type Reader interface {
    Read(p []byte) (n int, err error)
}
```

```go
// ❌ Нарушение [NAME-004] [NAME-008] [NAME-010]
const MAX_RETRIES = 3
type Url struct{}
func (user *User) GetName() string { return user.name }

// ✅ Правильно
const MaxRetries = 3
type URL struct{}
func (u *User) Name() string { return u.name }
```

## Исключения и граничные случаи
| Ситуация | Как поступить |
|----------|---------------|
| Коллизия имён пакетов при импорте | Использовать import alias — только при реальной коллизии. |
| Совместимость с внешним JSON/protobuf | Имя поля Go по правилам, соответствие внешнему ключу задавать тегом. |
| Одиночный метод с именем-акронимом | Регистр акронима сохраняется целиком (`ParseHTTP`, `ServeDNS`). |
