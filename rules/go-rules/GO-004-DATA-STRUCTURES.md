## Таблица правил
| ID | Правило |
|----|---------|
| DATA-001 | Преаллоцировать срезы через `make([]T, 0, n)`, когда размер известен или оценим. |
| DATA-002 | Преаллоцировать карты через `make(map[K]V, n)`. |
| DATA-003 | Перед bulk-append использовать `slices.Grow(s, n)` (Go 1.21+). |
| DATA-004 | Использовать arrays только для фиксированного, известного на компиляции размера. |
| DATA-005 | Строить строки в циклах через `strings.Builder`, а не `bytes.Buffer` и не `+`. |
| DATA-006 | Использовать `container/heap` для priority queue, `container/ring` для кольцевых буферов. |
| DATA-007 | Не применять `container/list` там, где достаточно среза (cache locality). |
| DATA-008 | Не хранить большие struct как value в карте — доступ копирует весь value. |
| DATA-009 | Использовать `unsafe.Pointer` только по 6 валидным паттернам из спецификации Go. |
| DATA-010 | Никогда не хранить указатель как `uintptr` между операциями — GC оставит dangling reference. |
| DATA-011 | Не полагаться на тайминг/алгоритм роста capacity — он меняется между версиями Go. |
| DATA-012 | Использовать `weak.Pointer[T]` для кэшей и canonicalization-карт (Go 1.24+). |

## Принцип
Правильная структура данных определяет и производительность, и корректность. Рост среза без преаллокации копирует backing array на каждом расширении (O(n) на рост), связные списки проигрывают срезам по cache locality, а `bytes.Buffer.String()` копирует байты там, где `strings.Builder` этого не делает. Отдельный класс ошибок — `unsafe.Pointer`: сохранение адреса в `uintptr` создаёт висячую ссылку, потому что GC вправе переместить объект.

| Понятие | Описание |
|---------|----------|
| `Preallocation` | Заранее заданная capacity, исключающая повторные копирования backing array. |
| `Backing array` | Массив, на который ссылается срез; при росте пересоздаётся. |
| `Value vs reference` | Arrays копируются целиком, slices и maps передают ссылку на данные. |

## Подробное описание

**[DATA-001]** Когда итоговый размер известен или оценим, задавайте capacity: `make([]User, 0, len(ids))`. Иначе каждый рост среза копирует весь backing array.

**[DATA-002]** Карты тоже преаллоцируйте: `make(map[string]*User, len(users))` — уменьшает рехеширование.

**[DATA-003]** Перед массовым append применяйте `slices.Grow(s, additionalNeeded)` — один рост вместо серии.

**[DATA-004]** Arrays — для фиксированного размера, известного на компиляции (`type MD5Digest [16]byte`). Для динамических данных используйте срезы: arrays копируются целиком как value.

**[DATA-005]** Строки в циклах собирайте `strings.Builder`. `bytes.Buffer` предназначен для двунаправленного I/O, и его `String()` копирует байты; конкатенация `+` квадратична.

**[DATA-006]** Для приоритетной очереди используйте `container/heap`, для фиксированных кольцевых буферов — `container/ring`, вместо самописных реализаций.

**[DATA-007]** `container/list` (связный список) оправдан лишь при частых вставках в середину. Для последовательного накопления берите срез — у него лучше cache locality.

**[DATA-008]** Не кладите большие структуры в карту по значению: каждый доступ к элементу копирует весь value. Храните указатель (`map[K]*Big`).

**[DATA-009]** `unsafe.Pointer` допустим только по шести валидным паттернам из спецификации Go (конверсии pointer↔pointer, срез↔массив и т.п.). Отклонения — потенциальная порча памяти.

**[DATA-010]** Никогда не сохраняйте `uintptr(unsafe.Pointer(p))` в переменную между операциями: сборщик мусора может переместить объект, и сохранённый адрес станет висячим. Конверсия в `uintptr` допустима только «в одном выражении».

**[DATA-011]** Алгоритм роста capacity — деталь реализации, меняющаяся между версиями Go. Не пишите код, зависящий от конкретного тайминга или коэффициента роста.

**[DATA-012]** Для кэшей и canonicalization-карт используйте `weak.Pointer[T]` (Go 1.24+): он позволяет GC собрать значение, когда на него нет сильных ссылок.

> **Важно:** `uintptr` — это число, а не ссылка. GC его не отслеживает (DATA-010). Сохранённый в переменную `uintptr` после перемещения объекта указывает в никуда.

## Пример

```go
// [DATA-001] преаллокация среза под известный размер
users := make([]User, 0, len(ids))

// [DATA-002] преаллокация карты
m := make(map[string]*User, len(users))

// [DATA-005] сборка строки через strings.Builder
var b strings.Builder
for _, s := range parts {
    b.WriteString(s)
}
result := b.String()
```

```go
// ❌ Нарушение [DATA-001] — рост среза в цикле, O(n) копирований
var results []Result
for _, item := range items {
    results = append(results, process(item))
}

// ✅ Правильно — capacity задана заранее
results := make([]Result, 0, len(items))
for _, item := range items {
    results = append(results, process(item))
}
```

Ориентир по версиям и пакетам:

| Go версия | Пакет/функция | Назначение |
|-----------|---------------|------------|
| 1.21+ | `slices`, `maps` | Обобщённые операции над контейнерами |
| 1.21+ | `slices.Grow` | Pre-grow перед bulk append |
| 1.24+ | `weak.Pointer[T]` | Кэши и canonicalization maps |
| stdlib | `container/heap` | Priority queue |
| stdlib | `container/ring` | Кольцевые буферы |

## Исключения и граничные случаи
| Ситуация | Как поступить |
|----------|---------------|
| Размер заранее неизвестен | Оставить `var s []T` и полагаться на append; преаллокация не нужна (DATA-001). |
| Частые вставки в середину | Допустим `container/list` вместо среза (исключение из DATA-007). |
| Системный вызов с указателем | `unsafe.Pointer`→`uintptr` только внутри одного выражения аргумента (DATA-010). |
