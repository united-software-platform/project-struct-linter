## Таблица правил
| ID | Правило |
|----|---------|
| SAFE-001 | Делать type assertion только через comma-ok (`v, ok := x.(T)`). |
| SAFE-002 | Не возвращать typed nil как интерфейс — возвращать untyped `nil`. |
| SAFE-003 | Инициализировать карту через `make()` до записи (запись в nil map паникует). |
| SAFE-004 | Не полагаться, что `append` копирует — при необходимости форсировать через `s[:len(s):len(s)]`. |
| SAFE-005 | Возвращать defensive copy из экспортируемых функций вместо внутренней ссылки на slice/map. |
| SAFE-006 | Не использовать `defer` в цикле — выносить в отдельную функцию. |
| SAFE-007 | Проверять границы перед сужающими числовыми преобразованиями (int64→int32 и т.п.). |
| SAFE-008 | Не сравнивать float через `==` — использовать сравнение с эпсилоном. |
| SAFE-009 | Проверять делитель на ноль перед делением. |
| SAFE-010 | Проектировать полезное zero value (`var mu sync.Mutex` пригоден без инициализации). |
| SAFE-011 | Предпочитать generics/`any` там, где это ловит несоответствия на компиляции. |

## Принцип
Многие ошибки в Go не падают сразу, а тихо портят данные: сужающее преобразование обрезает число, `append` переиспользует backing array и мутирует чужой срез, typed nil в интерфейсе не равен `nil`. Защитное программирование делает такие места явными: comma-ok вместо голого assertion, проверка границ перед преобразованием, defensive copy на границе API. Цель — чтобы некорректное состояние либо не возникало, либо обнаруживалось немедленно.

| Понятие | Описание |
|---------|----------|
| `Comma-ok` | Безопасная форма `v, ok := x.(T)`, не паникующая при несоответствии. |
| `Typed nil` | Nil-указатель, обёрнутый в интерфейс: `!= nil`, хотя значение внутри nil. |
| `Defensive copy` | Копия внутренних данных, отдаваемая наружу, чтобы вызывающий не мог их мутировать. |

## Подробное описание

**[SAFE-001]** Голое `v := x.(T)` паникует при несоответствии типа. Всегда используйте comma-ok: `v, ok := x.(T)` и обрабатывайте `ok`.

**[SAFE-002]** Typed nil указатель, положенный в интерфейс, делает интерфейс `!= nil`. Возвращайте из функций untyped `nil`, а не `(*T)(nil)`, если хотите семантику «ничего».

**[SAFE-003]** Nil map не имеет резервного хранилища — запись паникует. Инициализируйте через `make(map[K]V)` до первой записи.

**[SAFE-004]** `append` может вернуть срез, разделяющий backing array с исходным. Если нужна независимая копия — форсируйте через полную нарезку `s[:len(s):len(s)]` перед append либо `slices.Clone`.

**[SAFE-005]** Экспортируемые функции не должны отдавать наружу ссылку на внутренний slice/map — вызывающий сможет мутировать состояние. Возвращайте defensive copy.

**[SAFE-006]** `defer` выполняется при выходе из функции, а не на итерации цикла. `defer` в цикле накапливает отложенные вызовы до конца функции — выносите тело цикла в отдельную функцию.

**[SAFE-007]** Сужающие числовые преобразования (`int64`→`int32`, `float`→`int`) обрезают молча. Проверяйте границы перед преобразованием.

**[SAFE-008]** Арифметика float неточна (IEEE 754). Не сравнивайте через `==`; используйте `math.Abs(a-b) < epsilon`.

**[SAFE-009]** Целочисленное деление на ноль паникует. Проверяйте делитель перед делением.

**[SAFE-010]** Проектируйте типы так, чтобы zero value был пригоден: `var mu sync.Mutex`, `var buf bytes.Buffer` работают без инициализации. Это исключает целый класс nil-ошибок.

**[SAFE-011]** Где generics ловят несоответствие типов на компиляции — предпочитайте их динамическим assertion'ам; это переносит ошибку из runtime в build.

> **Важно:** typed nil (SAFE-002) — источник неуловимых багов: функция возвращает `var p *T` как `error`/интерфейс, и проверка `if err != nil` неожиданно истинна.

## Пример

```go
// [SAFE-001] безопасный assertion
if v, ok := x.(string); ok {
    use(v)
}

// [SAFE-003] инициализация карты до записи
m := make(map[string]int)
m["k"] = 1

// [SAFE-006] вместо defer в цикле — отдельная функция
for _, path := range paths {
    if err := processFile(path); err != nil {
        return err
    }
}

func processFile(path string) error {
    f, err := os.Open(path)
    if err != nil {
        return err
    }
    defer f.Close() // выполнится при выходе из processFile, не в конце цикла
    return handle(f)
}
```

```go
// ❌ Нарушение [SAFE-007] — молчаливое переполнение
var big int64 = 5_000_000_000
small := int32(big) // обрезано без предупреждения

// ✅ Правильно — проверка границ
if big > math.MaxInt32 || big < math.MinInt32 {
    return fmt.Errorf("значение %d вне диапазона int32", big)
}
small := int32(big)
```

## Исключения и граничные случаи
| Ситуация | Как поступить |
|----------|---------------|
| Assertion, где несоответствие — это баг программы | Допустим одиночный `x.(T)` внутри, если инвариант гарантирован и покрыт тестом (SAFE-001). |
| Внутренняя функция, не пересекающая границу API | Defensive copy не обязателен, если срез не уходит наружу (SAFE-005). |
| Точные денежные вычисления | Не float с эпсилоном, а целые (минимальные единицы) или decimal (SAFE-008). |
