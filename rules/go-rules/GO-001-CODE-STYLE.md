## Принцип
Стиль кода в Go — это не вкусовщина, а инструмент снижения когнитивной нагрузки. Единообразное форматирование, предсказуемый порядок объявлений и ранний возврат делают код читаемым любым членом команды и упрощают ревью. Большая часть правил автоматизируется инструментами (`gofmt`, `golangci-lint`), поэтому ручное соблюдение сводится к организационным решениям, которые инструмент проверить не может.

| Понятие | Описание |
|---------|----------|
| `Ранний возврат` | Выход из функции при ошибке/edge case до основной логики — уменьшает вложенность. |
| `Composite literal` | Литерал структуры/среза/карты; с именами полей устойчив к изменению порядка полей. |
| `Именованный bool` | Промежуточная переменная, дающая имя сложному условию. |

## Подробное описание

**[STYLE-001]** Строки длиннее 120 символов разбивайте по семантическим границам (после запятой в списке аргументов, по логическим операторам). Функции с четырьмя и более аргументами оформляйте по одному аргументу на строку — это упрощает diff и читаемость.

**[STYLE-002]** Используйте `:=` для инициализации ненулевыми значениями и `var` — когда нужно нулевое значение (`var buf bytes.Buffer`). Это делает намерение явным: `var` сигнализирует «нужен zero value».

**[STYLE-003]** Nil-карты паникуют при записи, поэтому карты и срезы, в которые будет запись, инициализируйте через `make()`. Nil-срез допустим только для чтения и append.

**[STYLE-004]** В composite literals всегда указывайте имена полей. Позиционные литералы ломаются молча при добавлении или перестановке полей структуры.

**[STYLE-005]** Обрабатывайте ошибки и граничные случаи ранним возвратом, а «счастливый путь» держите на нулевом уровне вложенности. Удаляйте `else` после блока с `return`.

**[STYLE-006]** Условия из трёх и более операндов выносите в именованные булевы переменные (`isReady := connected && authorized && !expired`) — это документирует смысл проверки.

**[STYLE-007]** Длинные цепочки `if-else`, ветвящиеся по одному и тому же выражению, заменяйте на `switch` — читается как таблица и легче расширяется.

**[STYLE-008]** Соблюдайте канонический порядок в файле: package doc → imports → constants → types → constructors → methods. Один primary type на файл, когда у него значимый набор методов.

**[STYLE-009]** Группируйте связанные объявления в блоки `const (...)` / `var (...)`. Blank imports (`_`) допустимы только в `main` и тестовых пакетах; dot imports в библиотечном коде запрещены — они загрязняют namespace.

**[STYLE-010]** Экспортируйте агрессивно-минимально: всё, что не является частью публичного API, держите unexported. Это сужает контракт пакета и облегчает рефакторинг.

**[STYLE-011]** В циклах используйте `strings.Builder` вместо конкатенации строк через `+` — избегаете квадратичной аллокации.

**[STYLE-012]** Форматирование — задача инструментов. Настройте `gofmt`, `gofumpt`, `goimports`, `gocritic`, `revive` в `golangci-lint` и `go vet`; не спорьте о форматировании вручную.

> **Важно:** Nil-карта не имеет резервного хранилища — запись в неё вызывает panic во время выполнения. Всегда инициализируйте карты до записи (STYLE-003).

## Пример

```go
// [STYLE-001] — длинный вызов разбит по одному аргументу на строку
mux.HandleFunc("/api/users", func(w http.ResponseWriter, r *http.Request) {
    handleUsers(
        w,
        r,
        serviceName,
        cfg,
        logger,
        authMiddleware,
    )
})

// [STYLE-004] — composite literal с именами полей
srv := &http.Server{
    Addr:         ":8080",
    ReadTimeout:  5 * time.Second,
    WriteTimeout: 10 * time.Second,
}
```

```go
// ❌ Нарушение [STYLE-007] — else-if цепочка скрывает наличие default
if debug {
    level = slog.LevelDebug
} else if verbose {
    level = slog.LevelWarn
} else {
    level = slog.LevelInfo
}

// ✅ Правильно — default-then-override через switch
level := slog.LevelInfo
switch {
case debug:
    level = slog.LevelDebug
case verbose:
    level = slog.LevelWarn
}
```

## Исключения и граничные случаи
| Ситуация | Как поступить |
|----------|---------------|
| Нужен nil-срез для «нет данных» | Оставляйте nil для семантики «отсутствие»; `make` — только при записи (STYLE-003). |
| Blank import драйвера БД | Допустим в `main`/init-пакете, но не в библиотеке (STYLE-009). |
| Автогенерированный код | Не форматировать и не переписывать вручную — управляется генератором (STYLE-012). |
