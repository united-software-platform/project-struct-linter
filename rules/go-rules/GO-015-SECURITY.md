## Таблица правил
| ID | Правило |
|----|---------|
| SEC-001 | Использовать parameterized queries (`$1`/`?`); не конкатенировать SQL. |
| SEC-002 | Генерировать токены/ключи через `crypto/rand`, не через `math/rand`. |
| SEC-003 | Не вызывать shell (`bash -c`) для внешних данных — запускать процесс с явными аргументами. |
| SEC-004 | Валидировать весь внешний ввод на границах доверия. |
| SEC-005 | Хешировать пароли через Argon2id или bcrypt, не MD5/SHA1. |
| SEC-006 | Шифровать через AES-GCM (аутентифицированное шифрование), не AES без аутентификации. |
| SEC-007 | Не хардкодить секреты — брать из окружения/секрет-хранилища. |
| SEC-008 | Сравнивать секреты через `subtle.ConstantTimeCompare`, а не `==`. |
| SEC-009 | Не возвращать наружу детализированные внутренние ошибки. |
| SEC-010 | Не игнорировать находки `-race` — гонки могут обходить авторизацию. |
| SEC-011 | Применять defense in depth и безопасные значения по умолчанию. |

## Принцип
Безопасность начинается с трёх вопросов: где границы доверия, что контролирует атакующий и какова область поражения (blast radius). Ответы определяют, где валидировать ввод и какие примитивы использовать. Базовый набор правил закрывает самые частые классы уязвимостей: инъекции (SQL/команды), слабую случайность, неаутентифицированную криптографию и утечку секретов. Принцип защиты по слоям (defense in depth) и безопасные значения по умолчанию снижают цену единичной ошибки.

| Понятие | Описание |
|---------|----------|
| `Trust boundary` | Граница, за которой данные становятся недоверенными и требуют валидации. |
| `Defense in depth` | Несколько независимых уровней защиты вместо одного. |
| `Constant-time compare` | Сравнение секретов за постоянное время, не выдающее данные через тайминг. |

## Подробное описание

**[SEC-001]** SQL стройте только через placeholders (`$1`, `?`). Конкатенация пользовательского ввода в запрос позволяет изменить его логику (SQL injection).

**[SEC-002]** Токены, session ID, ключи генерируйте через `crypto/rand`. `math/rand` предсказуем и позволяет угадать значение.

**[SEC-003]** Не запускайте команды через shell (`exec.Command("bash", "-c", ...)`) с внешними данными — shell интерпретирует метасимволы. Запускайте процесс напрямую с массивом аргументов.

**[SEC-004]** Валидируйте весь внешний ввод (HTTP-параметры, загрузки файлов, CLI-аргументы) на границе доверия до обработки.

**[SEC-005]** Пароли хешируйте через Argon2id или bcrypt с солью. MD5/SHA1 быстры и подбираются brute-force.

**[SEC-006]** Для шифрования используйте AES-GCM — он даёт и конфиденциальность, и аутентификацию. AES без аутентифицированного режима не защищает от подмены шифротекста.

**[SEC-007]** Секреты не хардкодьте — они попадают в историю VCS и логи CI. Берите из переменных окружения или секрет-хранилища.

**[SEC-008]** Секреты (токены, HMAC) сравнивайте через `subtle.ConstantTimeCompare`. Обычное `==` короткозамыкает и утекает информацию через тайминг.

**[SEC-009]** Наружу возвращайте обобщённые ошибки. Детализированные внутренние сообщения помогают атакующему картировать систему.

**[SEC-010]** Не игнорируйте находки детектора гонок: race condition в проверке прав может привести к обходу авторизации.

**[SEC-011]** Стройте защиту по слоям и выбирайте безопасные значения по умолчанию — так единичный промах не открывает всю систему.

> **Важно:** приоритизируйте по серьёзности — Critical чинится немедленно, High — в текущем спринте, Medium — в следующем, Low — по возможности.

## Пример

```go
// [SEC-002] криптостойкий токен
func generateToken() (string, error) {
    b := make([]byte, 32)
    if _, err := rand.Read(b); err != nil { // crypto/rand
        return "", err
    }
    return base64.URLEncoding.EncodeToString(b), nil
}

// [SEC-008] сравнение секрета за постоянное время
if subtle.ConstantTimeCompare(providedMAC, expectedMAC) != 1 {
    return ErrUnauthorized
}
```

```go
// ❌ Нарушение [SEC-001][SEC-003]
query := fmt.Sprintf("SELECT * FROM users WHERE name = '%s'", name)
exec.Command("bash", "-c", "convert "+userInput+" out.png")

// ✅ Правильно
db.QueryContext(ctx, "SELECT * FROM users WHERE name = $1", name)
exec.CommandContext(ctx, "convert", userInput, "out.png")
```

Уровни серьёзности:

| Уровень | Действие |
|---------|----------|
| Critical | Исправить немедленно |
| High | Исправить в текущем спринте |
| Medium | Исправить в следующем спринте |
| Low | Исправить при возможности |

## Исключения и граничные случаи
| Ситуация | Как поступить |
|----------|---------------|
| Неслучайный идентификатор без требований к секретности | `math/rand/v2` допустим, но не для секретов (SEC-002). |
| Легаси-хеши паролей (MD5/SHA1) | Перехешировать при следующем успешном входе пользователя (SEC-005). |
| Внутренние логи | Детализированные ошибки допустимы только во внутренних логах, не в ответе клиенту (SEC-009). |
